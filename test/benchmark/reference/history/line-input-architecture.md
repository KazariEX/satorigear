本轮聚焦一个意图：减少跨阶段保存的物理行事实，保留 BlockTokenStream、AST builders、inline pipeline 和精确 token 对应规则。最初的生产基线为 4a9c16d；后续归因已在同步上游 5fcdd43 后重建所有比较 bundle。没有重新接回直接 AST 大改，也不以零碎小改替代架构研究。

## 下一候选：把扫描期行状态与构建期位置索引分开

旧管线：

```text
source → 四字段物理行表 → 块识别与 token → 原 AST builders
                       └────────────────→ 全局定位器
```

拟议管线：

```text
source → 密集物理行起点索引 → 当前行读取器 / 当前逻辑作用域 → 原块 token
                         └────────────────────────────→ 原 AST builders 的定位器
```

这里只改变行输入。不会同时引入 AST 骨架、inline jobs/posts、语法专属 close 协议或新的增量收敛依据。

| 事实 | 持有者 | 生命周期 |
| --- | --- | --- |
| 每条物理行的 UTF-16 起点 | LineIndex，含需要的 EOF 点 | 供块扫描与 AST 定位共用 |
| 当前物理行的消费位置 | PhysicalRows | 当前扫描作用域，fork 只复制局部状态 |
| 当前行 end | 当前行读取器按需计算并缓存 | 当前行；不为所有物理行持久保存 |
| 物理行 next | 下一条物理行起点或 source EOF | 从同一索引取得 |
| 物理 prefix/lazy | 物理读取器的常量 0/false | 不写入每条物理记录 |
| 容器 prefix/lazy | 各容器当前逻辑行 | 仍由语法 scope 拥有 |
| 块结构及正文范围 | 原 BlockTokenStream | 原有协议，不改为 AST 计划 |

索引始终密集，不使用 sparse anchor，也不在 AST 阶段重新扫描源码恢复行号。所有物理换行都被索引；EOF 点令末尾换行后的行列无需另外的 End 字段。LF/CR/CRLF 共用一个模型。

这里要验证的新消费不变量是：语法循环消费当前行，临时几何只在当前行需要时形成；AST 定位只读取密集的行起点。不能把旧随机查询接口原封不动套在压缩索引上，让每次 end/next 查询重复派生几何。

## 已取得的信息充分性证据

1. 在冻结旧 bundle 中，仅替换 SourceLocator：从现有行表提取行起点，加入 EOF 点。其余所有代码不变。codegen/CSP 各通过 2614 份完整 AST/position 对照、4608 次编辑对照。这证明旧定位器所需信息可以只由起点向量提供。
2. 独立 LineIndex 内核从原文建立起点向量，在 2614 份公开 parse 结果的 158502 个 AST 位置点上与原坐标一致。覆盖官方例子、整份 spec 的 LF/CRLF/CR/mixed，以及 Rust/APIs 默认语法。
3. spec 有 9756 条物理行。新信息模型需要 9757 个位置点，活跃索引字段 39028B；旧四字段活跃内容 156096B。这是该索引的数据量，不是总堆节省或速度收益。
4. 旧 spec 的物理行查询计数：start 14991 次，end 11412 次，next 2932 次，prefixColumns 6556 次，lazy 1504 次；AST 定位调用 7361 次。这些是工作量诊断，不是耗时分解。

验证替换版仍然建立旧表，再复制起点，故没有对它跑性能；不能把它当作已经完成的新 parser。独立内核还没有接入 grammar 或实现完整增量更新，同样没有吞吐结论。

## 与历史否决路线的区别及必须证明的部分

- 历史 29/30/31/42 在旧随机行查询接口下缩减字段或拆类，仍重复派生 next/end，并曾增加接口分派或模式；已有回退/复杂度证据。新候选必须以当前行消费消除这种代价，不能只是重做编码或给旧接口加命中检查。
- 历史流式 token 原型用稀疏位置锚点、输出包装和额外定位维护，spec 回退 14% 以上。新候选保留完整密集的行起点，沿用全局单调定位器，不向语法或 token 输出层加入 checkpoint。
- 直接 AST 实验让位置依赖 AST span、增加任务和 post 阶段，并改变增量收敛。新候选不接受这些伴随变化。
- 此前省略 State=0 写入破坏 projected buffer 再 scan 的通用合同。这里不会修改该旧合同偷省写入；新的物理索引只有物理起点，其类型和当前逻辑作用域状态必须有清楚边界。

## 下一步实施边界

先将物理读取器和当前逻辑行消费者接到既有 token 输出，完成默认语法及位置验证，再做真实 spec ABBA/BAAB。不会对受限 grammar、重复建表的验证 shim 或单独扫描内核测得的速度作生产推断。

必须保持 codegen/CSP、token kind/范围/结构长度、定义 membership 和精确 token correspondence。引用定义的 prospective paragraph 生命周期、setext 正文末端、缩进 code 尾空行、容器物理换行身份都要通过公开语法验证。

增量阶段只替换物理位置索引的实现；重解析边界、whole-block 收敛和 inline 对应规则继续使用原算法。不得为了接通新索引再扩大任务到编辑缓存或 AST 所有权。

如果收益必须依靠额外坐标域、语法专属标记、输出 checkpoint 或跨阶段双重所有权维持，这条路线停止。当前状态是数据模型可行性研究，不是合入候选，100× 目标仍未达成。

## 独立后端实验：批量建立原物理行表

这条新路线保持现有按区间推进的 grammar、四字段 BlockLines、token、定位、AST 与增量算法，只替换物理行扫描的执行后端。先用 TextEncoder.encodeInto 将 UTF-16 source 编码到 Wasm memory，单次调用批量写出原四字段表，再同步复制到原 JS index。原 JS 扫描器作为模块不可用时的 fallback；block/inline codegen 和其 CSP fallback 保留。

标量内核 327B；SIMD 内核 428B，每次检查 16 个 UTF-8 字节，并跟踪原 UTF-16 偏移。内核大小只是冻结二进制的体积，没有 minify 收益，也不代表生产包装成本。研究使用 Node 文件加载器与显式二进制构造脚本，未设计生产分发。

| 生产 → 完整候选 | spec | 95% CI | 官方例子 | 95% CI |
| --- | ---: | --- | ---: | --- |
| 标量 Wasm + 编码/复制桥接 | +9.68% | [+6.53%, +12.93%] | +23.34% | [+22.17%, +24.53%] |
| SIMD Wasm + 同一桥接 | −2.30% | [−4.39%, −0.15%] | +19.64% | [+15.62%, +23.81%] |

SIMD 的完整 spec 结果有收益，例子集则明确回退，不能合入或更新累计倍数。没有增加语料大小阈值、profile 开关或另一套特殊 parser 来绕过结果；不在明确失败的守卫后继续确认 spec。

这条路线同时增加了需要处理的数据，因而不符合原本希望减少中间表示的方向。独立布局诊断中，spec 有 204706 个 UTF-16 code unit，编码后 205025B；当前桥接预留 614118B 输入区域和 3275312B 输出区域，Wasm memory 共 3932160B，另需将 156096B 活跃索引复制到原表。这些是该实现的 payload/保留区域大小，不是总堆测量，也不能据此精确分解耗时。

标量/SIMD 在 generated/CSP 下均通过 2614 份完整 AST/position 与 4608 次完整 feature 编辑对照；另各通过 128 组 BMP、非 BMP、孤立 surrogate、Unicode 分隔符的公开语法 AST/位置对照。两个 native 后端均诊断确认实际激活；强制禁用 WebAssembly 时，JS fallback 在 generated/CSP 下各通过 2614 份默认 AST/position 对照。大输入容量与内存增长失败行为尚未做产品准入。

本轮两个方向共 128 次严格 ABBA/BAAB observation，最长 299.35ms，所有命令使用 taskpolicy -c utility；没有重跑 remark 性能，生产源码未改。Wasm 证据见 native-line-kernel-0b724f4-node26-m1pro.json。除非先证明可以去掉编码/复制边界，否则停止此后端路线；批量执行的局部潜力不等于值得增加第二套执行后端。
