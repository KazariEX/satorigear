## 消除跨事件补修

旧路径中，反斜杠 scanner 或换行 lexer 先产生一个尚未覆盖物理换行的 HardBreak，随后再发出 Newline。构建器遇到 Newline，检查前一个 AST 子节点是否为 break，跳过普通软换行处理，并补修该节点的 position.end。

新路径中，两种硬换行语法都只产生一个完整 HardBreak：End 表示已经消费换行及续行空格；现有 Data 槽保留换行之后、剥除缩进之前的视图边界。break 自己的 builder 根据这个边界建立语义结束位置。Newline 现在只表达软换行，不再携带仅供补修使用的行首事实。

没有增加 token 字段、feature API、跨 parse 缓存或 block/增量协议。SourceView 和 AST 所有权不变，generated 与 CSP 同步。生产净增 3 行：反斜杠识别现在显式消费完整换行，AST 层删除了按前一个节点类型补修的位置分支。行索引和按区间推进能力不变。

## 验证与限制

194 项源码测试、构建、类型检查、变动文件 lint 通过。新增 3 项测试仅断言规范语法的输出文本及位置，覆盖反斜杠硬换行、引用块续行缩进和 LF/CR/CRLF；没有增加 parser-private 测试。最终构建的 bundle SHA-256 与受测文件一致。

Generated/CSP 各通过 2614 份完整 AST/position 对照、4761 次尾部/属性语法和编辑对照、4608 次完整 feature 配置编辑对照。另外各 384 组硬换行语法 AST 与原实现完整一致，单独的 384 次 edit feature 对照也通过；每个语法样例明确包含两个 break，所有 break 节点及位置与 canonical mdast oracle 一致。

这不等于所有完整 AST 都与 oracle 一致：384 组中有 240 组在原实现中就存在完整 AST 差异，包含容器末端位置与续行 Tab 文本；剩余 144 组完整相等。最初对照先在 baseline 上失败，其原始结果已保留，未将失败改写成完整规范通过。两个后端均没有候选新增差异。
