# Latin1 近期候选：Node 26

> 冻结实验记录（2026-11-15，Node 26.13.0 / M1 Pro）。文中工作区状态仅指测量时的快照。全部配对观测保留；JSON 中的 `$text` 在 [reproduction.json](reproduction.json) 的 texts 下按 SHA-256 查找。完整反汇编已裁剪，保留日志摘要、关键片段和原内容哈希。

本轮选出的 `main-fused-stream` 相对当时八路展开基线综合表现较好，但连续 Unicode 别名仍有明确回退。后续尾部统一、字段掩码和 writeLine 对照见[报告索引](README.md)；本页不描述最新工作区。

所有百分比均为耗时变化，负数更快。基线是本轮开始时暂存的八路展开版，不是用户未暂存的双循环版。运行时为 Node v26.13.0 / Apple M1 Pro。各比较使用四组 ABBA/BAAB、16 个新进程，构建、测试与性能测量串行进行。全部配对观测、95% 区间、输入哈希、源快照引用和验证摘要见同名 JSON。

## 完成完整矩阵的前三项

| 候选 | 10 项快速路径矩阵几何平均 | 普通行（2 KiB～1 MiB） | Unicode | 密集换行 | 主要未解决回退 |
|---|---:|---:|---:|---:|---|
| main-fused-stream：单事件循环，块内消费 CRLF、跨块顺序合并 | -12.72% | -18.35%～-19.84% | -25.35% | -16.76% | 连续别名 +4.61% |
| packed-stream：单掩码循环，顺序合并 CRLF | -12.35% | -18.52%～-20.13% | -27.28% | -15.29% | 普通 CRLF +4.58%；饱和 CRLF +13.73%；连续别名 +3.29% |
| row-nonnegative：前瞻 CRLF，非负字段索引 | -8.16% | -15.21%～-16.61% | -22.57% | +1.57% | 普通 CR +10.96%；连续别名 +4.75% |

几何平均对十项快速路径用例等权，排除了不进入 Latin1 的 256 字节控制项。它只描述这套矩阵，不能抵消某项回退，也不是生产负载的加权加速比。不同候选各自与同一冻结基线配对，候选之间没有直接配对比较，不能把 -12.72% 与 -12.35% 的差异当作已证明的相互胜出。

本轮首选的优势主要在于消除了上一候选的 CRLF 明确回退：普通 LF、CR、CRLF 分别为 +0.46%、+0.16%、-2.71%，95% 区间均包含零；饱和 LF、CR、CRLF 分别为 -2.53%、-6.21%、-2.67%，区间均低于零。连续别名仍为 +4.61%，区间 [1.21%, 8.14%]，不能解释为已经持平。

更早的 `pack-do` 完整矩阵几何平均为 -7.29%，普通 CR +13.54%、饱和 CRLF +8.48%、连续别名 +8.64%，不列入前三。

本轮 `main-fused-stream` 的 Node 26 `benchmark:parse`：规格文档耗时 **-6.32%**，95% 区间 **[-7.74%, -4.88%]**；652 个小示例 **-0.60%**，区间 **[-3.26%, +2.12%]**。小示例未进入 Latin1，其结果与持平相容。

上一候选 `packed-stream` 的 Node 26 `benchmark:parse`：规格文档耗时 **-5.11%**，95% 区间 **[-5.93%, -4.28%]**；652 个小示例 **+0.26%**，区间 **[-1.81%, +2.37%]**。这些小示例均未达到 Latin1 的入口长度，不能把它们的波动解释为 SWAR 收益。

`row-nonnegative` 的饱和 LF/CR/CRLF 分别约为 0%、+0.84%、+1.09%，比顺序合并版更均衡；但普通 CR 行的回退仍明确存在。它保留为另一条研究方向。

## 尾部统一实验

`main-padded-fusion` 在复制前清零最后一个八字节块，并为没有换行结尾的输入追加 LF 标记，让同一个事件循环处理尾行。行为验证通过，但用越界 `charCodeAt` 的 NaN 经 `| 0` 识别标记后，连续别名耗时增加约 163%，变宽行增加约 31%。

`main-padded-bounded` 改为显式检查 `at < limit` 后再读取字符。严重回退缓解，但普通 LF +12.93%（区间 [11.91%, 13.96%]）、连续别名 +13.08%（区间 [7.23%, 19.25%]）仍不可接受。Latin1 类虽缩至 100 行，目前没有足够性能依据采用。越界反馈是否为前一版本严重回退的直接原因尚未用 V8 日志证明；这里只能确认改动后的实测差异。

## 其他候选为何没有入选

`consume-view` 把确认后的 LF 从事件掩码中直接消费，并使用小端 DataView 读字。七项筛选中 Unicode -26.50%、长行 -19.43%、CRLF -2.63%，但 LF **+12.96%**。它尚未完成完整矩阵与压力矩阵，不能与上表的综合指标并列，也不能作为无回退方案。

## 本轮选出的实现

两个四字节事件循环合并为一个八位事件循环；两个掩码通过一次乘法压缩。命中后仍读取完整 UTF-16 单元，排除 Latin1 低字节别名。同一八字节块内确认 CRLF 后直接消费两位；跨块 CRLF 利用最近 CR 后的位置合并，避免在每个块入口增加处理分支。

字段索引保持四项对齐，利用 Node 字符串长度上限保证四倍行字段数小于 2³¹。显式非负整数范围避开了此前观察到的额外溢出/负值检查。原容量分段和至多七字符的尾部处理仍保留。

该快照 Latin1 类为 119 行；暂存版为 226 行，用户双循环版为 124 行。相较用户版本，主要简化是减少一套事件处理逻辑，文本行数减少很有限；不以压缩排版的行数作为验收依据。

工作区版本通过 Node 26 正常构建，以及：196 项测试、TypeScript 构建检查、ESLint，以及 13,408 次行几何、1,310 次 AST/位置、720 次增量编辑对比和 43,730 次尾部/UTF-16/容量验证。工作区与已测 main-fused-stream.ts 源快照完全一致。

目标仍未完成：下一步必须消除连续 Unicode 别名上的已知回退，并检查不同预热历史下的稳定性，再重新验收，不能仅凭 benchmark:parse 的收益收敛。

## 后续事件解码实验

以下候选均已撤回，工作区继续保留 `main-fused-stream`。各候选使用 Node 26，与冻结暂存基线配对；只有标为筛选的候选未跑完整十一项矩阵。

| 候选 | 普通 LF | 连续 Unicode 别名 | 结果 |
|---|---:|---:|---|
| main-xor-stream：共享减法，提前清位，位置按位或 | +13.41% | +5.37% | 不采用 |
| main-leading-stream：高位打包，直接 clz，位置按位或 | +14.39% | +8.71% | 不采用 |
| main-or-stream：仅将位置加法改为按位或（七项筛选） | +10.52% | +7.45% | 不采用 |
| main-leading-direct：高位打包，恢复位置加法 | +13.23% | +5.28% | 不采用 |
| main-shifted-stream：按事件间距移位，累计位置 | +13.52% | +3.97% | 别名区间跨零，但 LF 明确回退；饱和 CRLF +5.19%，不采用 |

进一步直接配对 `main-or-stream` 与 `main-fused-stream`，使用相同的完整十一项输入顺序，确认 LF 耗时 +10.61%，95% 区间 [9.36%, 11.88%]；Unicode +3.70%，区间 [3.16%, 4.25%]。其余快速路径项的区间均跨零。这次配对消除了先前完整矩阵与七项筛选的预热顺序差异。

V8 日志中，基线与 `main-fused-stream` 的别名用例正式计时期间均无反优化。上述两种位置表达式在 LF 阶段使用的机器码分别为 10,792 与 10,808 字节；字循环主体基本相同，主要差异是两个事件定位点的加法及溢出分支被 OR 替代、进入循环前常量初始化顺序变化，以及慢路径栈槽变化。没有证据支持“OR 版多了大量热循环加载”的解释，也尚未证明指令对齐或分支预测是根因。更短的机器码在这个配对中仍更慢。

## 反向输入历史验证

将完整矩阵与压力矩阵的输入顺序各自反转，保持各项输入、计时规则、四组 ABBA/BAAB 和运行时不变，再测本轮 `main-fused-stream` 对暂存基线。这里改变的是测试历史，不是实现中的输入分流。

反向完整矩阵的十项快速路径均更快，95% 区间全部低于零；但普通文本收益降至 -3.99%～-6.08%，长行降至 -2.37%。相反，无换行输入为 -16.72%，CRLF 为 -15.11%。这些变化说明原顺序下的收益不能推广为固定加速比。

反向压力矩阵中，连续 Unicode 别名 **+9.27%**，95% 区间 **[7.94%, 10.63%]**，比原顺序的 +4.61% 更差。饱和 CR 为 +2.37%，区间 [-0.02%, 4.81%]；区间跨零不能证明等效。其余压力项没有发现统计上明确的回退。

因此，当前候选仍只是保留供审阅的最好在研版本，不能按“全面无回退”验收。主分支恢复为原 `main-fused-stream`，源码与已验证快照完全一致，暂存区未改变。本轮五种新解码方案都没有取代它。

## 块宽、分阶段扫描与无终止标记查表

本轮继续只用 Node 26、原输入顺序、冻结暂存基线。所有已测候选都存在明确回退，因此没有替换主分支的 `main-fused-stream`。

| 候选 | 普通 LF | 普通 CRLF | 连续 Unicode 别名 |
|---|---:|---:|---:|
| main-wide16 | +5.33% | +6.26% | +3.74% |
| main-compact-events | +28.57% | +25.15% | +2.30% |
| main-padded-masks | +28.33% | +18.23% | +20.95% |
| main-positions-zero | +1.56% | +0.02% | +10.95% |
| main-positions-array | +2.72% | +2.78% | +8.15% |
| main-positions-constant | +11.98% | -0.46% | +9.45% |

`main-wide16` 将每次字扫描扩大到十六字符，长行 -22.44%、无换行 -7.84%，但没有消除换行类型之间的回退。行为验证扩展到全部十六种尾部长度与对齐，共 87,460 次尾部/容量检查；另外验证了全部 65,536 种十六位事件掩码。

`main-compact-events` 在同一缓冲区内将有效事件压紧，再单独生成行表；无需第二个按输入长度分配的缓冲区。`main-padded-masks` 去掉中间记录，在每个块内先过滤别名、合并 CRLF，再统一写入行表，并在字符读取之前排除 EOF 标记。两者都实现了单一行字段写入组，也通过了行为检查，但额外的事件处理没有带来综合性能收益。

`main-positions-zero` 用升序三位位置序列代替逐事件 clz，不需要尾部终止标记：零号位置只可能位于序列开头，非空掩码保证 do…while 的首次处理有效。全部 255 种非空位置模式验证通过。`main-positions-array` 换用连续普通数组；`main-positions-constant` 明确使用类名访问同一张表。三者均未达标。

V8 别名阶段的优化代码显示，通过 `this.positions` 访问 TypedArray 时，每个非空块都包含表的类型、长度和底层地址读取；明确的类引用未消除这些读取。后续仅进行构建、行为检查和编译日志检查的 `main-positions-module` 使用模块级 const，消除了类型检查，但长度和地址读取仍在。`main-positions-frozen` 使用冻结的模块级普通数组，索引访问变为调用，并出现相应的栈保存/恢复。后两项没有完整配对性能结果，不将它们列为已经实测性能失败的方案。

主分支已恢复原首选，源码哈希与此前完成正常构建及 196 项测试的快照完全一致，暂存区未变。当前已知的别名回退仍未解决。
