# field 计数掩码性能实测 — Node 26

> 冻结实验记录（2026-11-15，Node 26.13.0 / M1 Pro）。文中工作区状态仅指测量时的快照。全部配对观测保留；JSON 中的 `$text` 在 [reproduction.json](reproduction.json) 的 texts 下按 SHA-256 查找。完整反汇编已裁剪，保留日志摘要、关键片段和原内容哈希。

比较当前源码的两处 `field = field + 4 & 0x7FFFFFFF` 与 `field = field + 4`。其他源码、构建配置与语料完全相同。当前源码、暂存区和原有未暂存 diff 未改。

## 方法

Node 26.13.0 / V8 14.6.202.34-node.40 / Apple M1 Pro arm64。A 保留掩码，B 去掉掩码。以下均为 B 相对 A 的耗时变化：正数意味着去掉后更慢，负数意味着去掉后更快。方括号是配对块的 95% 区间，属于逐项区间，不是全矩阵同时置信区间。

扫描采用 11 项常规矩阵和 7 项压力矩阵，各按正序、反序执行，合计四组实验；每组四个 ABBA/BAAB 块、16 个独立进程。每项覆盖 N 到 N+7 的全部尾部长度，复用行表与 scratch，包含复制成本。每项 GC、100 ms 预热、GC、50 ms 稳定、200 ms 自然 GC 计时。一次操作扫描八份输入。

端到端执行原样的 test/benchmark/parse.bench.ts，通过加载钩子仅切换 satorigear 冻结构建；BENCHMARK_ENGINE=satorigear，保留 Mitata 默认设置。预先设定八个 ABBA/BAAB 块，共 32 个独立进程。全部测量进程串行运行，不带 V8 跟踪标志，不删除较慢观测。总计 96 个独立测量进程。

## 机器码证据的边界

本轮两个冻结 bundle 与上一轮机器码比较逐字节相同。保留掩码的典型热循环增量为 add + and；去掉后为 adds + b.vs，有时另有寄存器搬运。它确实能消除溢出检查分支，但运行时间还受整段代码调度、布局和优化历史等影响。本轮证明了场景相关的实际收益和代价，不能仅凭少一个分支认定保留掩码整体更快；具体差异的运行时成因没有在本轮作因果定位。

功能上，当前 Node 的 MAX_STRING_LENGTH 为 536870888；每行四字段，field 不超过 2147483552，因此去掉掩码不会改变合法输入的计数结果。去掉版本通过 13,408 次行几何、1,310 次 AST/位置、720 次增量编辑对比，以及 43,730 项尾部/UTF-16/容量检查；词检测公共校验为 696,864 项。
